# Qwen-Image-Layered and LayerDiffuse: how they produce coherent multi-layer images

Sources read 2026-11-07: the arXiv HTML of both papers, the Qwen GitHub README and HF card, the sd-forge-layerdiffuse README, and the local clone of rootonchair/diffuser_layerdiffuse. [paper] = verified from the paper, [repo] = from a README / card / script. Our measurements: [qwen-image-layered.md](../../docs/models/qwen-image-layered.md), [layerdiffuse-sdxl.md](../../docs/ideas-considered/models/layerdiffuse-sdxl.md).

## 1. Qwen-Image-Layered ([2512.15603](https://arxiv.org/html/2512.15603))

The released model works on images, not text: one RGB image in, N RGBA layers out (N variable) that alpha-composite back to the input. The layers are coherent by construction because they come from one image. 20B BF16, Apache-2.0, 2025-12-19.

- [paper] VLD-MMDiT handles a variable layer count; Layer3D RoPE adds a layer-index axis (target layers from 0, the condition image at −1); training uses up to 20 layers. Order comes from the layer index and compositing order; evaluation uses order-aware DTW that allows merging adjacent layers.
- [paper] No explicit description of how hidden regions are completed (end-to-end "without relying on external modules"); inpainting artifacts are named as a weakness of the LayerD baseline.
- [paper] RGBA-VAE: four channels, extended from the Qwen-Image VAE with alpha weights initialised to zero; beats the LayerDiffuse VAE on AIM-500. Training data: layers from real PSD files (psd-tools), non-overlapping layers merged, composites captioned with Qwen2.5-VL.
- [paper] A text-to-layers variant (Qwen-Image-Layered-T2L) is trained in Stage 2 and shown qualitatively; [repo] the released checkpoint is image-to-layers and text-to-multi-RGBA is "limited". Generating with Qwen-Image text-to-image first and then decomposing "further improves visual aesthetics". All layers come in one pass, unlike earlier methods that need "recursive inference, leading to error propagation"; [repo] any output layer can still be decomposed again.
- [repo] `QwenImageLayeredPipeline` (diffusers): `layers` (4; 3 and 8 shown), `resolution` 640 recommended (or 1024), 50 steps, `true_cfg_scale` 4.0; the prompt describes the whole image including occluded elements and does not control individual layers; optional (`use_en_prompt` lets the model caption). No VRAM figure.
- Editing: resize / reposition / recolour are plain layer operations; the repo's `src/app.py` decomposes and exports PPTX / ZIP / PSD, `src/tool/edit_rgba_image.py` edits one layer with Qwen-Image-Edit, `src/tool/combine_layers.py` recomposites bottom to top. The paper's comparison with flat editing (Fig. 7) is qualitative.

## 2. LayerDiffuse ([2402.17113](https://arxiv.org/html/2402.17113))

- [paper] Modes: single transparent image; joint fg + bg generation (each layer has its own latent and LoRA, rank 256; query, key and value concatenated across layers in every attention layer, the source of cross-layer coherence); foreground-conditioned background and background-conditioned foreground (condition latent kept clean); a two-stage variant with zero-initialised UNet input channels; ControlNet compatible; usable with community models. **Multi-layer generation is iterative**: background-conditioned foreground generation repeated, the existing layers blended into one RGB image as the condition each time.
- [paper] Limitation: a trade-off between clean reusable elements and harmonious blending (conditioning on the background bakes its illumination into the foreground). Speed at 30 steps on an RTX 4090: joint 5.71 s on SD1.5, 21.5 s on SDXL; two-stage SDXL about 4.37 s × 2.
- [repo] Released SDXL models: `layer_xl_transparent_attn` (better quality), `layer_xl_transparent_conv` (better prompt alignment, strong style influence), and the two-step conditionals `fg2ble`, `fgble2bg`, `bg2ble`, `bgble2fg`; **SDXL joint is "on hold", not released**. SD1.5 has `transparent_attn`, `joint` (batch divisible by 3: fg, bg, blend; prompts global + optional fg / bg / blend, e.g. "apple" / "floor in room" / "apple on floor in room"), `fg2bg`, `bg2fg` (batch divisible by 2). In every mode the model decides where objects go and how big they are; **no mode takes a user mask or box for placement**.
- [repo] The blended output goes through a VAE round trip, so it can differ from the true fg + bg (composite the real layers yourself); the SDXL bg-conditioned fg model "may be too lightweight"; examples use 20 steps, CFG 5-7; the global prompt can corrupt the background, so split prompts per layer. diffusers SDXL scripts (`test_diffusers_xl_bg2ble.py`: background + prompt → blend; `..._bgble2fg.py`: background + blend + prompt → transparent foreground) default to SDXL base 1.0, 896×1152, 20 steps, CFG 7.
- No primary source says whether it works with SDXL-derived community checkpoints beyond the paper's claim (Sec. 4.10).
