# FLUX-based layered models on fp16-only GPUs (T4) and weight provenance: sources (Nov 2026)

Second pass, 2026-11-09. Our fixes and measurements: [fp16-on-t4.md](../../docs/concepts/fp16-on-t4.md), [revealayer.md](../../docs/models/revealayer.md), [cld.md](../../docs/models/cld.md). [unverified] = no fetched source; [coordinator] = from an HF LFS hash comparison.

## 1. FLUX fp16 overflow: what diffusers and ComfyUI do

Both handle FLUX in fp16 with one thing only: a clamp to ±65504 after the residual add. Neither upcasts modulation, norm_out or the embedders; the only fp32/fp64 work is RoPE frequencies and the sinusoidal timestep embedding. Our `fp16_mixed` (fp32 residual, norms and gates, absmax-scaled linears) is strictly stronger, so a pure-noise result is unlikely to be a base-FLUX overflow: RevealLayer's own code or the GGUF/LoRA path is the more likely cause (confirmed later).

- **diffusers `transformer_flux.py`:** `clip(-65504, 65504)` after the residual in the single block and on `encoder_hidden_states` (text stream) only in the double block; timestep and guidance cast to the hidden dtype ×1000; RoPE via `ids.float()` and float64 freqs where supported. The clamp came from PR #9097 ("Flux inference with torch.half outputs NaN values"). A maintainer on a Sana analogue: the model was trained with the clamp and "never saw value out of the scope of (-65504, 65504)", so clamping is part of expected behaviour ([issue 10336](https://github.com/huggingface/diffusers/issues/10336)).
- **ComfyUI `comfy/ldm/flux/`:** `torch.nan_to_num(..., posinf=65504, neginf=-65504)` on `txt` (double block, img stream unguarded), on `x` in the single block and on the final `img`; Modulation, RMSNorm/QKNorm and LastLayer have no fp32 casts; `rope()` builds its scale in float64 and returns float32.
- Community fp16 builds: Disty0 FLUX.1-dev qint4 fp16 compute; sayakpaul NF4 package for T4.
- **T4 in practice:** FLUX dev runs on a free-Colab T4 in ComfyUI with fp8 or GGUF Q4/Q5 (about 15 GB; RAM about 12 GiB, a common crash); no published T4 s/it, no reports of fp16 NaNs there (suggests ComfyUI's clamp suffices). Analogues: RTX 3060 Ti 8 GB Q4_K_S `--lowvram` 90-150 s per 1024², 20 steps. Our point: RevealLayer 512 px, 12 steps, 69 s on a Kaggle T4. stable-diffusion.cpp runs FLUX GGUF on 4-6 GB; Forge supports GGUF FLUX.

## 2. CLD, ART+ and PrismLayers weights

- **CLD** ([thuteam/CLD](https://huggingface.co/thuteam/CLD), Apache-2.0; code `monkek123King/CLD`, the `thuteam` GitHub path 404s): files `decouple_LoRA/{adapter, layer_pe.pth, transformer}`, `pre_trained_LoRA`, `prism_ft_LoRA`, `trans_vae/0008000.pt`. Paper ([2511.16249](https://arxiv.org/html/2511.16249v2)): FLUX.1[dev], LoRA rank 64, Prodigy lr 1, batch 4, 25K iters at 1024² on the PrismLayersPro training split; ART's multi-layer transparent autoencoder as RGBA decoder; conditioning = boxes + original image + text (image to layers). No VRAM or time reported.
- **[coordinator, SHA-256]** CLD's `pre_trained_LoRA` is byte-identical to the mirror's `base/pytorch_lora_weights.safetensors` (the ART base LoRA), so the ART base LoRA is officially on HF under Apache-2.0. `prism_ft_LoRA` differs from the mirror's ART+ 100k LoRA; the config loads it as `artplus_lora_dir`, so it is either ART+ PrismLayersPro or CLD's own fine-tune (not settled).
- **PrismLayers** ([redredsheep/PrismLayers](https://github.com/redredsheep/PrismLayers), MIT): Drive folders `base_ckpt` (ART), `artplus_PrismLayersPro_ckpt`, `artplus_PrismLayersPro100k_ckpt` (1024 px), `transp_vae_ckpt`, `pre_fuse_lora_dir`, `classifier_ckpt`, `TIPS_ckpt`. Mirror `24yearsold/PrismLayers_ckpt` (5.56 GB, one uploader, no licence) lacks the non-100k ART+ variant.
- **ART / ART+** ([2505.22523](https://ar5iv.labs.arxiv.org/html/2505.22523)): ART trained from FLUX.1-[dev] on the 200K PrismLayers set; ART+ fine-tuned on PrismLayersPro (20K iters at 512² then 10K at 1024², batch 4); text + layout to layers with no input image; layouts from a reference image or an LLM (LLM layouts lag human ones); beats ART in about 57-60 % of user-study comparisons. Input JSON: `whole_image` {caption "This is a [STYLE] style image. …", height, width} plus a `layout` list of boxes, the first two full canvas; `multi_layer_gen/demo.py`. No GGUF or low-VRAM runs found.
- **LayerDiffuse-Flux** (RedAIGC, [HF](https://huggingface.co/RedAIGC/Flux-version-LayerDiffuse), AFL-3.0): LoRA + TransparentVAE on FLUX.1-dev, `demo_t2i.py` / `demo_i2i.py`, PyTorch 2.3 / CUDA 12.1, 11 open issues, 14 likes, no formal quality reports; ComfyUI_FluxLayerDiffuse port.

## 3. RevealLayer code hazards for fp16

Official `infer.py`: transformer and VAE in bf16, transparent decoder dtype unset, no offload, 30 steps, 1024 px hardcoded, `--max_layer` 12, refiner loaded with `strict=False` without checking missing keys. `custom_model_mmdit.py`: (1) ROI mask `torch.full(..., -1e9, dtype=hidden dtype)` → −inf in fp16 (NaN-safe only while rows are not fully masked); (2) `layer_pe` fp32 parameter only moved with `.to(device)`, so the add promotes or mismatches; (3) timestep/guidance cast to the hidden dtype ×1000; (4) the refiner `delta` add is unguarded; (5) a `Clamp` module is defined but never used; (6) it reuses diffusers' FluxSingleTransformerBlock (inheriting its clip only if the bundled diffusers has it). `adapter.py` HybridRefiner (4 blocks, dim 384): LayerNorm without affine, plain SDPA, gated residuals in the input dtype, only RoPE in float32. `custom_pipeline.py`: no VAE upcast (comment about "odd purple output", chunked decode of 16 latents), CFG combined in the latent dtype, position ids in the model dtype (fp16 integers exact only to 2048). The repo vendors its own `diffusers/`. Issue #3 (layer_pe 12 vs Refiner 32) is expected (the Refiner has its own `max_layers`=32). Code Apache-2.0; weights `qihoo360/RevealLayer`; datasets research-use. **ComfyUI-TBG-RevealLayer** (Ltamann) allows FLUX.1-dev in FP16/BF16/FP32 but not quantised transformers or FLUX.2; it downloads 4 files (about 697 MB) and applies the LoRA at 1.0.

No FLUX.2, Kontext or Qwen port of RevealLayer, CLD, ART or LayerDiffuse-Flux was found.
